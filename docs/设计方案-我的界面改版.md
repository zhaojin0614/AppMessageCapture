# 设计方案：「我的」界面改版——全局设置平铺 + 页面设置二级化

> 日期：2026-10-03　｜　状态：**已实施**（commit 58eadfd，经用户两轮调整）
> 目标：全局设置直接平铺在「我的」一级界面；单个界面的专属设置收进二级页；所有设置在「我的」均可找到。
>
> **最终调整（用户确认）**：
> 1. 消息页的筛选/屏蔽/查询/导出**保留在消息页原位置**，不迁入「我的」；
> 2. 生日页的导出/导入/闹钟权限**保留在生日页齿轮弹窗**，不迁入「我的」；
> 3. 因此「页面设置」组及两个二级设置页（消息页设置/生日页设置）**取消**，
>    SettingsScreen 解散后全部内容直接平铺进「我的」，无二级设置页。

## 四、交互规则

1. **模块开关联动**：记账管理 4 行跟随对应模块开关显隐（现有逻辑平移）；「页面设置」里消息页设置跟随「消息捕获」、生日页设置跟随「生日提醒」显隐；某组全空则整组隐藏。
2. **守卫不变**：三个功能 Tab 至少保留一个；「我的」永不可关，任何状态下设置可达。
3. **返回栈**：二级页 BackHandler 返回「我的」；「我的」Tab 切换按现有 SaveableState 保留状态。
4. **页面内快捷入口保留建议**：消息页顶栏的筛选/屏蔽图标、生日页齿轮**保留为快捷入口**（打开同一弹窗/二级页）——用户在具体列表场景下不必绕行「我的」；只把「设置的正式家」定在「我的」（见开放问题①）。
